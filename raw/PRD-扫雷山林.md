## 1. 产品概述

### 1.1 产品定位

一款微信小游戏形态的**单机扫雷**游戏，以“山林”自然质感为视觉基调。

- 无需登录，打开即玩。
- **经典模式**：无限局，难度可持久化（低 / 中 / 高 / 随机）。
- **闯关模式**：9 级倒计时递进挑战，进度本地持久化，可无限重试。
- 支持通过链接、微信搜索、分享海报二维码、好友分享卡片进入。

### 1.2 产品形态

| 维度 | 方案 |
| --- | --- |
| 平台 | 微信小游戏（非小程序） |
| 渲染 | Canvas 2D，全部界面自绘，不使用 WXML / WXSS |
| 后端 | 无业务后端；仅使用微信云函数生成小程序码 |
| 登录 | 全流程不强制微信登录 |
| 数据 | `wx.setStorageSync` 本地持久化全部进度、设置与纪录 |
| 音频 | `wx.createInnerAudioContext({ useWebAudioImplement: true })` |

### 1.3 非目标

首版**不实现**：

- 联机对战、排行榜
- 体力 / 次数限制
- 内购
- 动态难度调整
- 用户账号体系、云端存档同步
- 朋友圈内直接对局

## 2. 用户进入路径

| 进入方式 | 实现要求 | 落地行为 |
| --- | --- | --- |
| **链接进入** | 使用微信明文 URL Scheme 或 URL Link，指向已发布版本启动页，可携带来源参数 | 进入模式选择页；读取启动参数，不直接进入对局 |
| **搜索进入** | MP 平台配置“功能直达”或搜索入口，召回词：`扫雷`、`单机扫雷`、`山林扫雷`、`经典扫雷` | 进入模式选择页 |
| **分享海报二维码** | 云函数 `wxacode.getUnlimited` 生成小程序码，`scene` 携带场景标识 | 扫码进入模式选择页；根据 `scene` 展示轻提示，如“好友通过了第 5 关” |
| **好友分享卡片** | 使用小游戏分享能力，卡片标题与图片为山林风格 | 进入模式选择页 |

**统一原则**：所有外部入口均落地到模式选择页，不直接落地到具体对局，避免状态异常。

### 2.1 启动参数规范

| 来源 | 字段 | 取值 | 行为 |
| --- | --- | --- | --- |
| 小程序码 | `query.scene` | `c` / `p1`…`p9` | 模式选择页展示对应轻提示，不自动开局 |
| URL Scheme / URL Link | `query.from`、`query.src` 等 | 任意字符串 | 忽略未知参数，不中断启动 |
| 好友卡片 | `query.from` | `card` | 进入模式选择页 |
| 朋友圈单页模式 | `scene` 场景值 | `1155` | 只展示引导与可玩兜底，不依赖登录态与完整存储 |

所有参数解析必须容错：字段缺失、类型异常、`scene` 非法时静默忽略。

## 3. 信息架构与页面状态

### 3.1 状态机

```
BOOT（启动 / 参数解析）
  → MODE_SELECT（模式选择）
      ├→ CLASSIC_PLAY（经典对局）
      │    → CLASSIC_END（结算）→ CLASSIC_PLAY / MODE_SELECT
      └→ LEVEL_SELECT（闯关选关）
           → LEVEL_PLAY（闯关对局）
               ├→ LEVEL_FAIL（失败）→ LEVEL_PLAY / LEVEL_SELECT
               └→ LEVEL_SUCCESS（通关）→ POSTER_PREVIEW（海报预览）
```

叠加层（不改变主状态）：设置面板、结果面板、海报预览、轻提示 Toast。

### 3.2 模式选择页内容

- 游戏标题“扫雷·山林”。
- **经典模式**按钮：显示当前难度（低 / 中 / 高 / 随机）。
- **闯关模式**按钮：显示当前进度，如“第 3 关”或“已通关”。
- 设置入口：音效开关、振动开关、难度设置入口（也可在经典对局内提供）。
- 分享入口：可生成“当前状态海报”。

### 3.3 闯关选关页内容

- 9 关网格，每关显示关卡号、棋盘规格、雷数、最佳用时。
- 未解锁关卡显示锁形标识，不可点击。
- 已通关关卡可重复挑战。
- 返回模式选择。

## 4. 经典模式

### 4.1 难度参数

| 难度 | Key | 棋盘（列×行） | 雷数 |
| --- | --- | --- | --- |
| 低 | `low` | 9×9 | 10 |
| 中 | `mid` | 16×16 | 40 |
| 高 | `high` | 16×30 | 99 |
| 随机 | `random` | 每局从低/中/高等概率抽取 | — |

### 4.2 难度持久化与随机规则

- 首次进入默认“中”。
- 用户设置低 / 中 / 高后持久化，后续经典模式沿用。
- 用户选择“随机”后，**每局开始时**从低 / 中 / 高等概率随机抽取，并持久化“随机”状态。
- 对局内必须有当前难度指示（随机模式显示本局实际难度，并标注“随机”）。

### 4.3 对局规则

| 规则 | 说明 |
| --- | --- |
| 无限局 | 单局结束可立即再来一局，不消耗次数 |
| 首点安全 | 首次点击格子及其周围 8 格不布雷，至少保证首点不是雷 |
| 胜利 | 所有非雷格子被翻开 |
| 失败 | 翻开地雷格；展示全部地雷分布；提供“再来一局” |
| 计时 | 记录单局用时；仅用于展示与本地最佳纪录比较，不导致失败 |

**计时起点**：经典模式在首次翻开格子时开始计时，翻雷后停止。

## 5. 闯关模式

### 5.1 结构

- 共 9 关，逐级递增。
- 每关独立倒计时；倒计时归零或踩雷即失败。
- 可无限重试，不消耗次数 / 体力。
- 通过第 N 关解锁第 N+1 关，进度本地持久化。
- 已通关关卡可重复挑战。

### 5.2 关卡参数（首版基线）

| 关卡 | 棋盘（列×行） | 雷数 | 倒计时 |
| --- | --- | --- | --- |
| 1 | 8×8 | 8 | 90s |
| 2 | 9×9 | 10 | 80s |
| 3 | 10×10 | 14 | 75s |
| 4 | 12×12 | 22 | 70s |
| 5 | 14×14 | 30 | 65s |
| 6 | 16×16 | 40 | 60s |
| 7 | 16×20 | 55 | 55s |
| 8 | 16×24 | 72 | 50s |
| 9 | 16×30 | 99 | 45s |

### 5.3 闯关规则

- 首点安全同样适用。
- **进入对局后立即开始倒计时**，首点安全不额外延长。
- 最后 10 秒：倒计时数字放大 / 脉冲提示，并播放轻微滴答声（受音效开关控制）。
- 失败：停留当前关，可重试。
- 通关：首次通关或刷新本关最佳用时，进入通关页并提供“生成分享海报”；未刷新纪录也可手动生成海报，但不自动弹出。
- 通关判定：所有非雷格翻开，且在倒计时结束前完成。

**切后台处理**：应用隐藏时暂停计时，回到前台继续，避免因系统弹窗或来电判负。

## 6. 核心交互：短按翻开、长按插旗

### 6.1 手势定义

| 操作 | 行为 | 触发条件 |
| --- | --- | --- |
| **短按** | 翻开格子 | 按下后抬起，持续时间 **< 300ms**，且手指移动未超出格子边界 |
| **长按** | 标记状态循环：隐藏 → 安全标记 → 疑似地雷 → 地雷标记 → 隐藏 | 按住 **≥ 300ms**，触发时立即 `wx.vibrateShort({ type: 'light' })`（振动开关开启时） |

### 6.2 边界规则

- 隐藏格：短按翻开；长按进入标记循环，不翻开。
- 已标记格：短按**同样执行翻开**（若实际是雷则失败，标记消失）；长按继续循环标记。
- 手指按下后移动超出格子边界：取消本次短按 / 长按判定。
- 棋盘外的滑动、多指触摸不触发翻开或标记。
- 标记状态视觉必须**形状差异优先**，不能仅靠颜色区分。

### 6.3 标记计数

- 顶部显示“已标记地雷数 / 总雷数”，仅统计“地雷标记”（第 3 态）。
- 安全标记、疑似标记不计入计数。

### 6.4 标记循环与展开的交互约定

- 自动展开（BFS）遇到已标记格子时**跳过**，不自动清除玩家标记。
- 手动短按已标记格时，清除该格标记并执行翻开逻辑。

## 7. 游戏核心逻辑与数据结构

### 7.1 格子数据结构

```js
{
  isMine: false,
  adjacentMines: 0,
  revealed: false,
  mark: 0 // 0 隐藏, 1 安全, 2 疑似, 3 地雷
}
```

### 7.2 棋盘生成

- 根据难度 / 关卡生成 `cols × rows` 二维数组。
- **首点安全**：在首次翻开时布雷，排除首点及其 8 邻域。若剩余可布雷格不足，至少保证首点不是雷。
- 计算每个非雷格周围 8 邻域雷数。
- 随机布雷使用 Fisher–Yates 洗牌，保证等概率。

### 7.3 翻开与展开

- 翻开非雷格：
  - `adjacentMines > 0`：仅翻开该格。
  - `adjacentMines === 0`：使用**队列 / BFS** 展开周围未翻开的非雷格，避免递归栈溢出。
- 翻开地雷：立即失败，记录被踩中的格子。
- 每次翻开后检查胜利：所有非雷格 `revealed === true`。
- 已翻开格再次点击为空操作（不计步、不播音效）。

### 7.4 状态持久化 Key

| Key | 内容 |
| --- | --- |
| `settings` | `{ sound: true, vibrate: true }` |
| `classicDifficulty` | `'low' \| 'mid' \| 'high' \| 'random'` |
| `classicBest` | `{ low, mid, high }`，各难度最佳用时（秒，null 表示无） |
| `levelProgress` | `{ unlocked: 1, bestTimes: { "1": 62, ... } }` |

**容错**：所有读取必须校验类型与取值；存储损坏、清缓存后自动回退默认值，不崩溃。

## 8. 视觉风格：山林

### 8.1 关键词

墨绿基调、木质与石材质感、柔和自然光、低饱和高明度辅助色；避免科技感 / 霓虹感 / 纯扁平化。

### 8.2 色彩建议

| 元素 | 建议实现 |
| --- | --- |
| 背景 | 深墨绿到灰绿低对比渐变，叠加极淡雾气 / 树影纹理 |
| 未翻开格 | 深灰绿或木褐色，轻微颗粒 / 石片质感，柔和边缘 |
| 已翻开格 | 浅苔藓绿或暖灰褐，与未翻开形成明度差 |
| 数字 | 蓝 / 绿 / 红 / 深蓝体系，降低饱和度；字体高可读 |
| 安全标记 | 浅色叶片 / 对勾，低饱和 |
| 疑似地雷 | 问号图标，中等醒目 |
| 地雷标记 | 深色雷形或禁止符号，最高醒目 |
| 面板 / 按钮 | 木质圆角面板；主按钮苔藓绿，次按钮半透明深色 |

### 8.3 适配

- Canvas 按逻辑分辨率适配，棋盘居中。
- 高难度格子过小时优先压缩间距，不进一步缩小格子。
- 闯关倒计时固定在棋盘上方，最后 10 秒脉冲放大。
- 分享海报落地页需适配朋友圈预览模式场景值 `1155`，避免依赖登录态和完整本地存储。

### 8.4 可访问性

- 标记以**形状差异**区分：叶片（安全） / 问号（疑似） / 雷形（地雷）。
- 数字采用形状可辨、对比度足够的低饱和配色，避免仅靠颜色区分雷区状态。
- 所有点击目标具备视觉按压反馈。

## 9. 音效

### 9.1 触发点

| 事件 | 音效 |
| --- | --- |
| 翻开格子 | 短促点击 / 翻石声 |
| 标记切换（安全 / 疑似 / 地雷） | 短促标记声，可与翻开不同 |
| 取消标记 | 短促取消声 |
| 踩雷失败 | 明显失败音 |
| 闯关通关 | 胜利音 |
| 倒计时最后 10 秒 | 轻微滴答声（每秒一次），受总开关控制 |

### 9.2 技术约束

- 首次音效必须在 **`touchstart`** 用户交互中解锁播放，不能在异步回调中首次播放。
- 使用 `wx.createInnerAudioContext({ useWebAudioImplement: true })`，每种音效**复用实例**，禁止每次点击新建。
- 提供全局音效开关，状态持久化；静音不阻断游戏。
- 监听音频中断结束（`wx.onAudioInterruptionEnd`），恢复音频上下文。
- 音频资源使用本地 WAV，避免网络加载延迟。

## 10. 分享能力

### 10.1 分享形态

分享核心产物为**竖版海报图片**，包含当前用户状态摘要与游戏小程序码。其他用户识别 / 扫描二维码进入游戏。

### 10.2 海报规格

- 尺寸：750×1334。
- Canvas 离屏绘制。
- 内容：
  - 顶部：游戏名“扫雷·山林” + 山林背景。
  - 中部：状态文案。
  - 二维码区：小程序码，尺寸 ≥ 280×280px。
  - 底部：“长按识别二维码，来山林里扫雷”。

### 10.3 状态文案与 scene

| 场景 | 文案示例 | 二维码 scene |
| --- | --- | --- |
| 经典模式结束 | “我刚在【中】难度用了 XX 秒，来挑战我” | `c` |
| 经典模式进行中 | “正在山林里扫雷，【高】难度进行中” | `c` |
| 闯关通关 | “通过了第 N 关，用时 XX 秒” | `pN`（如 `p5`） |
| 闯关失败 | 不生成分享海报 | — |

### 10.4 分享路径

| 目标 | 实现 |
| --- | --- |
| 微信好友 / 群 | 海报预览页“分享给好友”，优先 `wx.showShareImageMenu`；不支持则保存相册并引导手动发送 |
| 朋友圈 | “保存到相册”，用户自行发布；不在代码中直接唤起朋友圈发布 |
| 好友分享卡片 | 右上角菜单 / 页面按钮，使用小游戏分享卡片能力，落地模式选择页 |

### 10.5 二维码生成

- 云函数调用 `wxacode.getUnlimited`。
- `width` ≥ 280；`scene` ≤ 32 字符，首版使用 `c` 或 `pN`。
- 返回二进制 Buffer，转 base64 或临时文件供 Canvas `drawImage`。
- 前端读取启动参数 `scene`，在模式选择页展示轻提示。
- 若云函数不可用：降级为**无二维码海报**，不阻塞游戏主体。

### 10.6 分享卡片

- 标题使用山林风格文案，如“来山林里扫雷，看看谁先清完这片雾气”。
- 图片使用本地海报缩略图或游戏主视觉。
- 路径统一落地模式选择页，携带 `from=card`。

## 11. 技术实现约束

### 11.1 项目结构

小游戏工程根为 `minigame/`，开发者工具导入该目录；仓库根目录只放文档、预览、测试与开发脚本。

```
minigame/                  // ★ 微信开发者工具导入此目录
  game.js                  // 小游戏入口
  game.json                // 小游戏配置
  project.config.json      // 开发者工具项目配置（compileType: game）
  js/
    config.js              // 难度、关卡参数、颜色、时间阈值
    storage.js             // 本地持久化封装与容错
    game-core.js           // 布雷、首点安全、翻开、BFS 展开、胜负判断
    renderer.js            // Canvas 2D 绘制、脏区更新、山林视觉
    input.js               // 触摸事件、短按 / 长按判定
    audio.js               // 音效实例复用、解锁、开关、中断恢复
    share.js               // 海报 Canvas、保存、分享、二维码
    levels.js              // 闯关参数与进度
    main.js                // 状态机与页面流转
  audio/                   // 本地音效资源（WAV）
  cloudfunctions/
    getQrCode/             // 生成小程序码

仓库根（开发工作区，不导入开发者工具）
  docs/                    // PRD、验收、开发者工具排错、截图
  preview/                 // 浏览器预览（模拟 wx API）
  tests/                   // Node 单元测试
  tools/                   // 预览构建、交互回归、截图、音频生成
  README.md
  package.json
```

### 11.2 渲染要求

- 使用 `wx.createCanvas()`，优先开启高性能模式（基础库支持时）。
- 棋盘采用**脏区更新**，仅重绘变化格子；倒计时等局部 UI 单独更新。
- 使用 `requestAnimationFrame` 驱动，不每帧全量重绘。

### 11.3 输入要求

- `touchstart` 记录时间、坐标、格子索引；`touchmove` 判断是否超出边界；`touchend` 判定短按。
- 长按使用定时器，300ms 触发后标记已处理，`touchend` 不再执行翻开。
- 长按触发后立即振动反馈。
- 按钮点击与棋盘手势分区处理，互不干扰。

### 11.4 启动参数

- 使用 `wx.getLaunchOptionsSync()` 读取 `scene`、`query`。
- 支持 `scene` / `query.scene` 为 `c`、`pN` 的提示；不因参数异常中断启动。
- 监听 `wx.onShow` 处理再次进入时的参数变化。

## 12. 非功能需求

| 类别 | 要求 |

## 14. 实现判定与偏差记录（开发基线补充）

以下为实现阶段对原始需求中未明确或物理受限处的判定，均不扩大产品范围：

1. **高难度格子尺寸**：16 列在 375pt 宽屏幕上即使去掉边距也无法同时满足“16 列可见 + 每格 ≥28pt”；16×30 在竖屏高度上进一步受限。
   - 实测：390×844 下 16×16 约 21–22pt/格，16×30 约 19–20pt/格；375×667 下 16×30 约 14–15pt/格。
   - 实现策略：优先压缩格间距（最小 1pt），再按棋盘适配缩放格子；不把格子缩到无法辨认；长按阈值与手势判定不因格子小而失效。
   - 该偏差属于物理约束，已在 README 与 `docs/ACCEPTANCE.md` 中单列，并列为真机上线前评估项。首版不引入缩放/平移棋盘，避免未定义的功能扩展。
2. **经典计时起点**：首次有效翻开时开始，未点击前计时器显示 `00:00`。
3. **切后台**：暂停计时（经典用时与闯关倒计时），回前台继续。
4. **自动展开遇旗**：跳过已标记格，不清除玩家标记。
5. **随机难度**：持久化值为 `random`，模式选择页显示“随机”，进入对局后 HUD 显示本局抽中的实际难度。
6. **朋友圈单页（1155）**：正常可玩，但只使用内存态与默认设置，不读写持久化纪录，并展示轻量引导条。
7. **未生成二维码时**：海报仍完整输出（状态文案 + 装饰性二维码位），并明确提示“小程序码暂不可用”，不阻塞分享。
8. **音效资源**：使用项目内生成的本地 WAV，避免外链与首播延迟。
9. **分享能力检测**：`wx.showShareImageMenu` 不存在或调用失败时，自动保存海报并提示用户手动发送。
10. **结算面板可关闭**：经典/闯关结算面板提供关闭按钮，关闭后可查看完整棋盘（含失败时的全部地雷）；点击棋盘任意格可重新打开结算，避免“展示地雷”被面板永久遮挡。
11. **胜利补旗**：胜利时自动把所有地雷标记为地雷状态，顶部计数与棋盘一致为 `总雷数 / 总雷数`，属于结算展示，不改变胜负逻辑。
12. **设置面板暂停计时**：打开设置时暂停经典用时与闯关倒计时，关闭后继续；避免玩家在设置中消耗闯关时间。
13. **音效与振动的开关时机**：开关立即生效并持久化；音效关闭时不播放任何游戏音效，静音不阻断游戏。
14. **小屏自适应**：菜单卡片与闯关卡片高度按屏幕高度压缩；矮屏下隐藏次要的关卡倒计时行，保证最佳成绩与规格信息不重叠。
15. **云函数版本参数**：前端根据 `getAccountInfoSync()` 传递 `envVersion`（develop / trial / release），云函数按该版本生成小程序码；未获取到时回退 release。
16. **云函数权限**：`getQrCode/config.json` 声明 `wxacode.getUnlimited` openapi 权限；未部署时前端 6 秒超时降级为无二维码海报。
17. **分享卡片图**：通过运行时离屏 Canvas 生成 500×400 卡片图，避免新增静态图片资源；顶部菜单转发落地模式选择页。
18. **结算海报入口**：经典失败同样允许生成海报（文案为“踩了雷”），PRD 文案表未禁止；闯关失败不生成海报。

## 15. 风险与待真机验证项

1. **长按 300ms 阈值**：首版固定 300ms，上线后按真机反馈在 250–400ms 间调整。
2. **图片分享 API 兼容性**：`wx.showShareImageMenu` 在目标基础库的支持需真机验证；不支持时降级保存相册。
3. **小程序码 `page` 参数**：按平台文档验证；首版留空或指向启动页，`scene` 通过启动参数读取。
4. **朋友圈传播链路**：依赖保存海报后手动发布，首版接受。
5. **闯关倒计时参数**：按本文基线实现，上线后按通关率调整，不在首版引入动态难度。
6. **开发工具与真机差异**：字体（宋体 / 苹方）渲染、振动强度、音频解锁时机需在真机复核。
